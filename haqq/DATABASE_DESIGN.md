# HAQQ — Database Design

PostgreSQL 16 with the `vector` extension. Schema is created only through Alembic
(`backend/alembic/versions/0001_initial_schema.py`, autogenerated from `app/models.py`, plus HNSW indexes).

## Tenancy rule
Every tenant-owned row carries `org_id`; project-owned rows also carry `project_id`. API code never queries by id
alone: `core/deps.get_owned()` checks `org_id` **and** project access and returns 404 (not 403) for foreign rows, so
existence is not disclosed. Aggregations start from `accessible_project_ids()`.

## Indexes
`org_id` on all tenant tables; `(project_id, ref)` unique for events/entitlements/claims; `deadlines(org_id, status,
due_date)`; `documents.sha256`; HNSW `vector_cosine_ops` on `document_chunks.embedding` and `clauses.embedding`.

## Money and dates
`NUMERIC(18,2)` for money, `NUMERIC(18,3)` for quantities, `DATE` for contractual dates, `timestamptz` for events.

## Retention
`organizations.data_retention_days` stores the tenant policy. **Automated purge is not yet implemented** (see
limitations); deletion of an organisation cascades to all its data.
