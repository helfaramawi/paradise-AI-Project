# سير عمل n8n لمنصة Future Mirror AI

سبعة ملفات جاهزة للاستيراد في n8n، ملف لكل سيناريو أتمتة يظهر في صفحة **الأتمتة** بالمنصة.

كل سير عمل يبدأ بطريقة من اثنتين:
- عبر Webhook، وهو ما يستدعيه زر **تشغيل** في المنصة.
- تلقائياً حسب جدول زمني بتوقيت القاهرة.

بعدها يتصل بواجهة برمجة المنصة ويرسل ملخصاً بالبريد الإلكتروني.

تمت تجربة الملفات السبعة على n8n 1.72.1 (الإصدار الموجود في docker-compose.yml) مع بيانات العرض التجريبية، واستُقبلت الرسائل على خادم بريد تجريبي.

| الملف | متى يعمل | ماذا يفعل | البريد |
|---|---|---|---|
| `scheduled_analysis.json` | كل اثنين 06:00 + Webhook | يعيد تحليل كل قرار سبق تحليله ولم يُرفض، على أحدث نسخة من البيانات. إذا أُرسل `decision_id` يعيد تحليل هذا القرار فقط | ملخص إلى `FM_N8N_ALERT_EMAIL` |
| `erp_sync.json` | يومياً 02:00 + Webhook | يسحب بيانات التكاليف (قراءة فقط) من كل موصل حالته «متصل»: D365 أو SAP أو REST أو SQL. إذا تغيرت البيانات تُنشأ نسخة جديدة منها | فقط عند تغيّر البيانات أو فشل المزامنة |
| `review_notification.json` | Webhook | عند تقديم استراتيجية للاعتماد يرسل للمعتمدين اسم القرار والأدوار المطلوبة | إلى `FM_N8N_ALERT_EMAIL` |
| `approval_workflow.json` | الأحد إلى الخميس 09:00 + Webhook | يجمع الاعتمادات المعلقة ويرسل لكل دور لم يعتمد بعد (المدير المالي، الرئيس التنفيذي، القانونية...) قائمته | رسالة لكل دور (`FM_N8N_ROLE_EMAILS`) |
| `kpi_monitor.json` | يومياً 07:00 + Webhook | يقارن آخر النتائج الفعلية بنطاق التوقع (P10–P90) لكل قرار | تنبيه فقط عند خروج مؤشر عن نطاقه |
| `post_decision_tracking.json` | أول كل شهر 08:00 + Webhook | يذكّر الفريق بالشهر المطلوب تسجيل نتائجه الفعلية لكل قرار معتمد. إذا أُرسلت النتائج إلى الـ Webhook يسجلها في المنصة | تذكير إلى `FM_N8N_ALERT_EMAIL` |
| `execute_contractor_notice.json` | Webhook | **سيناريو ذو أثر، وتم تأمينه.** المنصة تمنع التشغيل الفعلي (السياستان GOV-003 وGOV-014). حتى لو سُمح به، يرسل هذا السير لإدارة الموارد البشرية طلباً للتنفيذ اليدوي فقط، ولا يتصل أبداً بالمتعاقدين ولا بأنظمة الموارد البشرية أو ERP | إلى `FM_N8N_HR_EMAIL` |

## الإعداد (مرة واحدة)

1. **عرّف المنصة بمكان n8n.** أضف إلى ملف `.env`:
   ```
   FM_N8N_BASE_URL=http://n8n:5678
   ```
   إعدادات اختيارية في `.env` (القيم المعروضة هي القيم الافتراضية):
   ```
   FM_N8N_FROM_EMAIL=future-mirror@example.com    # عنوان المرسل
   FM_N8N_ALERT_EMAIL=approvers@example.com       # الملخصات والتنبيهات
   FM_N8N_HR_EMAIL=hr@example.com                 # طلبات إخطارات المتعاقدين
   FM_N8N_ROLE_EMAILS={"cfo":"cfo@company.com","ceo":"ceo@company.com","legal":"legal@company.com"}
   FM_N8N_API_EMAIL=cfo@futuremirror.demo         # المستخدم الذي يدخل به n8n إلى المنصة
   FM_N8N_API_PASSWORD=FutureMirror!2026
   ```
   في الاستخدام الفعلي أنشئ مستخدماً مخصصاً بدور المدير المالي، أو أي دور يملك `automation.run` و`dataset.write` و`decision.run` و`outcome.record`، وضع بيانات دخوله هنا.

2. **شغّل المنصة مع n8n:**
   ```
   docker compose --profile automation up -d --build
   ```
   يفتح n8n على http://localhost:5678، وفي أول مرة يطلب إنشاء حساب مالك.

3. **أضف حساب البريد.** في n8n اختر **Credentials ← Add credential ← SMTP**، ثم أدخل مثلاً:
   - Office 365: الخادم `smtp.office365.com`، المنفذ `587`، بدون SSL/TLS، مع اسم المستخدم وكلمة المرور.
   - Gmail: الخادم `smtp.gmail.com`، المنفذ `465`، مع تفعيل SSL/TLS واستخدام «كلمة مرور التطبيقات» وليس كلمة المرور العادية.

4. **استورد الملفات.** في n8n اختر **Workflows ← Add workflow ← ⋯ ← Import from File** لكل ملف. أو استورد الملفات السبعة مرة واحدة من مجلد المشروع:
   ```
   docker compose cp automation/n8n n8n:/tmp/fm-workflows
   docker compose exec n8n n8n import:workflow --separate --input=/tmp/fm-workflows
   docker compose --profile automation restart n8n
   ```

5. **أكمل كل سير عمل.** افتحه واضغط على عقدة البريد، واختر حساب SMTP من الخطوة 3، ثم **Save**، ثم فعّل **Active** أعلى اليمين. الـ Webhook والجدولة لا يعملان إلا والسير مفعّل.

## التجربة

- **من المنصة:** في صفحة **الأتمتة** اختر سير العمل وشغّله مع إلغاء وضع المحاكاة (dry-run). تظهر الحالة **delivered**، ويظهر التشغيل في قائمة **Executions** في n8n.
- **من سطر الأوامر:**
  ```
  curl -X POST http://localhost:5678/webhook/future-mirror/kpi_monitor -H "Content-Type: application/json" -d "{}"
  ```

إذا لم يجد سير العمل ما يُبلَّغ عنه (لا تغييرات، لا مؤشرات خارج النطاق، لا اعتمادات معلقة) فإنه ينتهي دون إرسال بريد.

## الأمان

- سير العمل يقرأ البيانات فقط. التغييرات الوحيدة التي يجريها داخل المنصة هي: بدء تشغيل تحليل، وإنشاء نسخة بيانات من مزامنة للقراءة فقط، وتسجيل النتائج الفعلية.
- لا يكتب أي سير عمل في أنظمة ERP أو الموارد البشرية أو أي نظام أعمال آخر.
- الإجراءات ذات الأثر تظل ممنوعة بسياسات الحوكمة في المنصة.
- بيانات n8n (سير العمل وحسابات البريد) تُحفظ ضمن كل نسخة احتياطية بواسطة `ops\backup.bat`.
