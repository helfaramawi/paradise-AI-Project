# Architecture

## 1. Guiding constraints

1. **LLMs generate and critique hypotheses. Deterministic and statistical models calculate the numbers.** The simulation engine imports nothing from the agent layer.
2. **Authority is enforced in code, outside any prompt.** The governance engine can deny a strategy that every agent supports.
3. **Never disguise mock results as real execution.** Every run records its mode (`rule_based` or `llm_augmented`). Presentation pacing is reported separately from compute time. Synthetic data carries provenance labels.
4. **A modular monolith in the MVP.** One API process, one database, one reverse proxy. The boundaries between modules are clean enough to split them later without rewriting.

## 2. System context

```
 Browser (React SPA, EN/AR, RTL)

     ▼

     ▼

  ├─ api/            REST routers, RBAC dependencies, validation   │
  ├─ services/       pipeline · events · audit · dossier · reports │
  ├─ agents/         LangGraph orchestrator + 10 agents            │
  │      └─ llm.py   optional provider (Anthropic/OpenAI/Ollama)   │──► LLM API (optional, narration only)
  ├─ simulation/     NumPy/SciPy/SimPy engine (pure functions)     │
  ├─ governance/     declarative policy engine                     │
  ├─ connectors/     read-only ERP adapters, file import           │──► ERP (read-only)
  └─ automation/     n8n webhook client (dry-run default)          │──► n8n (optional)
     │ SQLAlchemy 2 / Alembic
     ▼
 PostgreSQL 16 (SQLite supported for dev/tests)
```

## 3. Technology decisions

| Area | Choice | Why | Trade-off / alternative |
|---|---|---|---|
| API | FastAPI + Pydantic v2 | typed contracts, OpenAPI for free, async SSE | — |
| ORM / migrations | SQLAlchemy 2 + Alembic | mature; one migration path for PostgreSQL and SQLite | — |
| Database | PostgreSQL 16 | integrity, JSON columns, on-prem friendly | SQLite for zero-setup dev and tests |
| Orchestration | **LangGraph** `StateGraph` | explicit graph, parallel fan-out with a reducer, checkpointer | in-memory checkpointer only (see limitations) |
| Agent reasoning | deterministic analytical modules with an optional LLM narration layer | reproducible and testable; works offline and on-prem; never fabricates numbers | without an LLM the narratives are templated text, labelled as such in the UI |
| Simulation | NumPy (vectorised Monte Carlo), SimPy (DES) | fast enough for live sliders (~150 ms for 3 futures × 1 000 draws plus sensitivity and DES) | SciPy is available but not needed for the current distributions |
| Policy engine | in-process declarative JSON rules, modelled on OPA's input → decision approach | no extra service in the MVP; unit-testable; policies are data in the database | OPA/Rego sidecar is a documented next step; call sites would not change |
| Real-time updates | Server-Sent Events, events persisted in `workflow_events` | one-way streams, survive reconnects (replay from the event id), work through nginx | WebSockets not needed for one-way streams |
| Background execution | daemon thread per run | no broker in the MVP | a restart marks in-flight runs `failed` (they are not silently lost); Redis/RQ or Celery is the scaling path |
| Redis | **not used** | no queue, cache or pub/sub needed at MVP scale | add with a worker queue |
| Frontend | React 18, TS strict, Vite, Tailwind, shadcn-style components, Recharts, React Flow, Framer Motion | the requested stack | components are hand-written in the shadcn style rather than generated by the CLI |
| i18n | own context + typed dictionary (≈350 keys per language), `dir` switching, `Intl` with `ar-EG` | full RTL and localised digits without a heavy library | — |
| Reports | ReportLab (with Arabic shaping via arabic-reshaper + python-bidi), openpyxl | pure Python, no headless browser | PDF layout is functional, not designer-grade |
| Auth | JWT HS256 + PBKDF2-SHA256 (240k iterations) | standard-library hashing, no native deps | OIDC/SAML SSO in the backlog |

## 4. Request and data flows

### 4.1 Decision analysis

```
POST /decisions (auto_run) ──► DecisionRun(queued) ──► thread: execute_run
   LangGraph: intake → data_validation → agent_assignment
              → [strategy | cfo | coo | hr | delivery | legal | risk]   (parallel, retry ×3, timeout)
              → scenario_generation → quantitative_simulation
              → agent_court (phase-2 agents, Red Team, responses, collision detector)
              → risk_assessment (risk register + feasibility search)
              → governance_review (policy engine per future + agent-execution probe)
              → executive_recommendation
   every transition ─► workflow_events row ─► SSE stream to browser
   end ─► persist findings, evidence, objections, collisions, scenarios, simulation run/results,
          risks, governance evaluations, recommendation; audit event
```

### 4.2 What-if

`POST /simulation/run` is stateless by default: it returns the full simulation in about 150 ms and drives the Three Futures sliders. With `persist=true` it stores a `what_if` simulation run carrying its own input fingerprint.

### 4.3 Approval

`POST /decisions/{id}/approval-requests` re-evaluates governance on the persisted run. If any policy denies the strategy, the request is created as `blocked` (and audited). Otherwise it is `pending`, with `required_roles` taken from policy. Each verdict checks role membership and separation of duties, and governance is re-checked at final approval.

## 5. Traceability

Every simulation result links to `simulation_runs` (seed, iterations, input fingerprint = SHA-256 over model id/version, dataset, controls, parameters and economics) → `simulation_models` (version, parameters) → `dataset_versions` (checksum, provenance, validation). Agent findings link to `agent_executions` and carry `evidence_records` that reference exact simulation or dataset paths. Every consequential action writes a hash-chained `audit_events` row.

## 6. Security model (summary — see GOVERNANCE_MODEL.md)

- JWT bearer authentication; login rate limiting; PBKDF2 password hashing.
- RBAC: 8 roles, 19 permissions, checked by FastAPI dependencies on every route.
- Tenant isolation: every query is scoped by `tenant_id`; cross-tenant ids return 404 (tested).
- Prompt-injection hygiene: user text is sanitised and delimited as untrusted data; LLM output is never parsed into actions.
- Secrets live only in the environment; connector config refuses secret-like keys.
- Security headers in the API and nginx; the container runs as non-root (uid 10001).
- External writes are disabled (GOV-003), and agents can never execute (GOV-002).

## 7. Scaling path

1. Run uvicorn with `--workers N`. Each worker can run analyses; SSE reads from the database, so any worker can stream any run.
2. Move execution to a queue (Redis + RQ/Celery) and the LangGraph checkpointer to PostgreSQL (`langgraph-checkpoint-postgres`) so runs resume after a restart.
3. Split the simulation engine into its own service if heavier models arrive (it is already pure functions over Pydantic inputs).
